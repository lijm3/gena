# 钩子机制（Hooks）方案

> 目标：把日志、审计、追踪、策略注入这类**旁路能力**从主循环里剥出来，挂在生命周期事件上。新增/调整一项旁路能力只需要改 `.claude/hooks.json` 与一个外部脚本，不动 `agents/main_agent.py`。

## 1. 背景

### 1.1 现状（散落的旁路逻辑）

- `auto_compact` 前手写的 transcript 落盘（`agents/main_agent.py` 内嵌）
- 未追踪的 `utils/llm_logger.py` / `utils/log_sanitize.py`：在 `core/llm_client.py` 调用点旁路注入日志/脱敏
- `BackgroundManager` 通知队列、`lead` 收件箱：每轮 `_preprocess` 里硬拼装注入
- `loop guard` 触发（`MAX_AGENT_ROUNDS` / `MAX_TOOL_CALLS` / `LoopDetector` / `ProgressTracker`）目前只能 `print`，外部系统看不到

再加一两个旁路能力（敏感词审计、调用配额、PII 脱敏、tool 调用计费），主循环会迅速变成"圣诞树"。

### 1.2 设计参照

- **`tests/hook.py`**（仓库内教学版 Hook 系统）：subprocess + 三事件（`SessionStart` / `PreToolUse` / `PostToolUse`）+ exit code 0/1/2 + 可选 JSON stdout（`updatedInput` / `additionalContext` / `permissionDecision`）+ `.claude/.claude_trusted` 工作区信任门。
- **Claude Code** 的 hooks（事件命名、协议风格、配置位置 `.claude/`）。

本方案沿用 `tests/hook.py` 的核心协议，**不另起一套**，便于复用社区脚本与心智模型。

## 2. 目标与非目标

### 2.1 目标
- 在不修改 `MainAgent.agent_loop` 主体的前提下，引入工具级 / 会话级生命周期事件
- 三处独立循环（`MainAgent`、`subagent.run_subagent`、`TeammateManager._loop`）**全部接入同一套** HookManager，避免审计盲区
- 主流程**默认零开销**：未配置 `.claude/hooks.json` 或工作区未信任时，调用路径只多一次空 dict 查找
- 钩子失败**不能挂掉**主循环（异常隔离）
- 与现有 `ToolResult`、loop guard、`ToolDispatcher`、`safe_subprocess_run` 兼容

### 2.2 非目标（本期不做）
- 不引入异步钩子（subprocess 同步执行，超时即中止）
- 不做插件加载机制（Python entrypoint / setuptools），只支持外部命令
- 不替换 `MessageBus` / `BackgroundManager`，它们是 agent 间通信，与 hook（agent 与外部观测者之间的事件）正交
- 不实现 Claude Code 全部事件（先三件套，按需扩展）

## 3. 事件清单

### 3.1 Phase 1（最小可用 —— 与 `tests/hook.py` 对齐）

| 本方案事件 | Claude Code 对应 | 触发时机 | Context 字段 | 可影响主流程 |
|---|---|---|---|---|
| `SessionStart` | `SessionStart` | REPL 启动 / `MainAgent.__init__` 完成 | `agent_role`（`lead`/teammate 名/`subagent`）, `cwd` | 仅注入 message |
| `PreToolUse` | `PreToolUse` | 每个 `tool_use` block 执行**前** | `tool_name`, `tool_input`, `agent_role`, `round`, `call_index` | 阻断 / 改写 input / 注入 message |
| `PostToolUse` | `PostToolUse` | 工具执行**后**（含异常） | 上面字段 + `tool_output_text`, `tool_output_status`（来自 `ToolResult` 前缀）, `duration_ms`, `error`（如有） | 仅注入 message |

Phase 1 事件名与 Claude Code 一一对应，便于复用社区钩子脚本。

### 3.2 Phase 2（按需扩展，**先不实现**）

| 本方案事件 | Claude Code 对应 | 用途 |
|---|---|---|
| `UserPromptSubmit` | `UserPromptSubmit` | 入口审计、敏感词拦截 |
| `Stop` | `Stop` | Lead Agent 完成响应、flush 外部日志 |
| `SessionEnd` | `SessionEnd` | REPL 退出收尾；1.5s 硬超时（仿 Claude Code） |
| `SubagentStop` | `SubagentStop` | `run_subagent` 返回时（gena 的 subagent 即 Claude Code 的 Task 工具） |
| `PreCompact` | `PreCompact` | `auto_compact` 前；把 transcript 落盘迁出去 |
| `LLMRequest` / `LLMResponse` | **（无对应，gena 自有）** | 把 `llm_logger` / `log_sanitize` 从代码迁出去；Claude Code 没有 LLM 级钩子，因为它的 LLM 调用是内部不可见 |
| `GuardTriggered` | **（无对应，gena 自有）** | loop-detector / budget / progress 命中时上报 metrics；Claude Code 没有等价的循环防护层 |

Claude Code 的 `Notification` 事件**不计划支持** —— gena 没有"等待用户输入"这类需要外部通知的状态。

Phase 2 在 Phase 1 稳定一段时间后**独立开 PR**，避免一次性铺太宽。

## 4. 配置

### 4.1 文件位置

`.claude/hooks.json`（沿用 `.claude/` 目录约定，与已存在的 `.claude/settings.local.json` 同级）。

> 与 `tests/hook.py` 用的 `WORKDIR/.hooks.json` 略有区别 —— 选 `.claude/` 是因为：① 已有目录、不污染仓库根；② 对齐 Claude Code 习惯；③ 便于在 `.gitignore` 里整目录忽略。
> 兼容方案：HookManager 优先读 `.claude/hooks.json`，其次回退 `.hooks.json`，方便从教学版迁过来的脚本不改路径。

### 4.2 Schema

```json
{
  "hooks": {
    "SessionStart": [
      { "command": "python hooks/announce_session.py" }
    ],
    "PreToolUse": [
      { "matcher": "bash",      "command": "python hooks/audit_bash.py" },
      { "matcher": "write_file","command": "python hooks/guard_paths.py" },
      { "matcher": "*",         "command": "python hooks/log_call.py" }
    ],
    "PostToolUse": [
      { "matcher": "*", "command": "python hooks/metrics.py" }
    ]
  }
}
```

字段：
- `matcher`：工具名精确匹配；`"*"` 匹配全部；缺省视作 `"*"`。可选。
- `command`：shell 命令（与 `tests/hook.py` 一致用 `shell=True`，Windows 下天然兼容 `python ...` / `bash -c ...`）。必填。

### 4.3 信任门

只在以下任一条件满足时执行钩子：
1. `.claude/.claude_trusted` 文件存在（与 `tests/hook.py` 一致）
2. HookManager 以 `sdk_mode=True` 构造（保留接口，预留 SDK 场景）

未通过信任检查时，`run_hooks` 直接返回空结果，**不报错、不打印**（保持安静）。这是为了让 clone 仓库后第一次跑的人不被任意脚本执行。

## 5. Hook 执行协议

完全沿用 `tests/hook.py`：

### 5.1 输入（环境变量）

```
HOOK_EVENT       事件名
HOOK_TOOL_NAME   工具名（SessionStart 时为空）
HOOK_TOOL_INPUT  JSON 序列化的 tool_input（截断 10000 字符）
HOOK_TOOL_OUTPUT 字符串化的 tool_output（仅 PostToolUse；截断 10000 字符）
```

外加 gena 特有：

```
HOOK_AGENT_ROLE   "lead" / teammate 名 / "subagent"
HOOK_ROUND        当前主循环轮次（int 字符串）
HOOK_CALL_INDEX   当前轮内第几个工具调用
HOOK_OUTPUT_STATUS  PostToolUse: ToolResult 前缀（DONE/CHANGED/NO_CHANGE/ERROR）
HOOK_DURATION_MS    PostToolUse: 工具执行耗时
```

> 字符串截断在 Hook 端做，避免环境变量过大被系统拒绝。具体长度上限做成常量 `HOOK_ENV_VALUE_MAX = 10000`。

### 5.2 输出（exit code）

| Exit | 语义 | gena 内行为 |
|---|---|---|
| `0` | 继续 | 若 stdout 是合法 JSON，按 §5.3 解析；否则忽略 |
| `1` | 阻断 | 仅 `PreToolUse` 有意义：跳过本次工具执行，向模型返回 `[Hook 阻断] {stderr}` 作为 `tool_result`；`PostToolUse`/`SessionStart` 的 `1` 退化为 `2`（注入 stderr 作为 message） |
| `2` | 注入 message | stderr 内容作为 `additionalContext` 拼到 `tool_result` 末尾（PreToolUse 拼到前缀，PostToolUse 拼到后缀） |
| 其它 | 视作错误 | 记 `[hook error]`，按 `0` 继续 |

### 5.3 结构化 stdout（exit 0 时可选）

```json
{
  "updatedInput": { /* PreToolUse 改写 tool_input */ },
  "additionalContext": "string",
  "permissionDecision": "allow" | "deny"
}
```

- `updatedInput`（仅 PreToolUse）：覆盖 `tool_input`。多个钩子串接，后者基于前者结果。
- `additionalContext`：注入到 `tool_result`，等价于 exit 2 的 stderr。
- `permissionDecision`：`"deny"` 等价于 exit 1。

非 JSON 的 stdout 当作普通日志打印一行（前 100 字符），不影响主流程。

### 5.4 超时

- 默认 `HOOK_TIMEOUT = 30s`
- `SessionEnd`/`Stop`（Phase 2）单独定 `1.5s` 硬超时
- 超时不阻断主流程：记录日志，按 exit 0 处理
- 实际生产环境（Claude Code）的 `TOOL_HOOK_EXECUTION_TIMEOUT_MS=600000`（10 分钟），本项目走教学值 30s，作为常量暴露便于调整

### 5.5 异常隔离

```python
try:
    r = safe_subprocess_run(...)   # 走 utils/encoding_utils 处理 Windows 编码
    # 按 exit code 处理
except subprocess.TimeoutExpired:
    log_hook_timeout(...)
except Exception as e:
    log_hook_error(...)
# 任何分支都返回 result，不向上抛
```

任何钩子异常**绝不**让主循环挂掉。

## 6. 在 gena 中的接入点

### 6.1 新增模块

```
managers/hook_manager.py
    class HookContext (dataclass)        # tool_name/tool_input/agent_role/round/...
    class HookResult (dataclass)         # blocked/messages/updated_input/...
    class HookManager
        def __init__(self, config_path=None, sdk_mode=False, agent_role="lead")
        def run_hooks(self, event: str, ctx: HookContext) -> HookResult
        def is_active(self) -> bool      # 信任门 + 配置存在
```

- 用 `dataclass` 而非 `dict` 当载体（system prompt 已提到 IDE 补全 / 类型安全）
- HookManager 实例**按 agent_role 区分**：lead/subagent/各 teammate 共享同一份 `.claude/hooks.json`，但 `HOOK_AGENT_ROLE` 不同，钩子脚本可按角色过滤

### 6.2 `main.py` — REPL 启动

```python
# 当前：
agent = MainAgent(...)
agent.run_repl()

# 改造：
hook_mgr = HookManager(agent_role="lead")
hook_mgr.run_hooks("SessionStart", HookContext(agent_role="lead", cwd=str(WORKDIR)))
agent = MainAgent(..., hook_manager=hook_mgr)
agent.run_repl()
```

### 6.3 `agents/main_agent.py` — 主 Agent

只改 `_execute_tools`（不动 `agent_loop` 主体、不动 `_preprocess`、不动 loop guard）：

```python
# 当前（简化伪代码）：
for block in tool_use_blocks:
    handler = dispatcher.get_handler(block["name"])
    output = handler(**block["input"])
    results.append({"type": "tool_result", "tool_use_id": block["id"], "content": str(output)})

# 改造：
for idx, block in enumerate(tool_use_blocks):
    ctx = HookContext(
        tool_name=block["name"], tool_input=dict(block["input"]),
        agent_role="lead", round=self._round, call_index=idx,
    )
    pre = self.hooks.run_hooks("PreToolUse", ctx)
    prefix = "\n".join(f"[Hook] {m}" for m in pre.messages)

    if pre.blocked:
        results.append({"type": "tool_result", "tool_use_id": block["id"],
                        "content": f"{prefix}\n[Hook 阻断] {pre.block_reason}".strip()})
        continue

    # updatedInput 改写
    tool_input = pre.updated_input or ctx.tool_input

    t0 = time.monotonic()
    try:
        result = dispatcher.get_handler(block["name"])(**tool_input)
        error = None
    except Exception as e:
        result, error = f"Error: {e}", str(e)
    duration_ms = int((time.monotonic() - t0) * 1000)

    # PostToolUse —— ctx 上挂 output/status/duration
    ctx.tool_output_text = str(result)
    ctx.tool_output_status = _extract_toolresult_status(result)
    ctx.duration_ms = duration_ms
    ctx.error = error
    post = self.hooks.run_hooks("PostToolUse", ctx)
    suffix = "\n".join(f"[Hook] {m}" for m in post.messages)

    content = f"{prefix}\n{result}\n{suffix}".strip()
    results.append({"type": "tool_result", "tool_use_id": block["id"], "content": content})
```

要点：
- **loop guard 计数器照常 ++**：阻断 = 调用发生过但拿到合成结果。否则恶意钩子可以让模型无限重试。
- **`compress` 工具特例不变**：仍由主循环检测 `block["name"] == "compress"` 走 `manual_compress=True` 分支；钩子仍然能在 `PreToolUse` 看见 `compress` 调用并记录/审计。
- **`_extract_toolresult_status`** 工具函数：识别 `[DONE]/[CHANGED]/[NO_CHANGE]/[ERROR]` 前缀，找不到时返回 `"UNKNOWN"`。

### 6.4 `agents/subagent.py` — 子 Agent

`run_subagent` 内部有硬编码的工具 handler 表 + 30 轮内循环。改造点：

- 入参增加 `hook_manager`（caller 传入 `MainAgent` 持有的同一实例，但**重置 agent_role**为 `"subagent"`）
- 工具执行 for 循环位置插入与 §6.3 相同的 Pre/Post 调用
- 不需要 `SessionStart`（子 agent 不是会话；如果要，挪到 Phase 2 作为 `SubagentStart`）

> Subagent 自己**没有** loop detection / progress / budget，所以钩子在这里的价值反而更高（外部审计是唯一观测窗口）。

### 6.5 `managers/teammate_manager.py` — 队友（线程）

`TeammateManager._loop` 在线程里跑独立 LLM 循环，工具集硬编码。改造：

- `TeammateManager.__init__` 接 `hook_manager`，每个队友实例传 `agent_role=<teammate-name>`
- 工具循环位置插入 Pre/Post
- `SessionStart` 在队友线程启动时触发一次（context 里标 `agent_role`）

> 注意：钩子在线程内**仍然同步**执行。Hooks 阻塞队友线程不影响主线程，所以这里其实更宽容。

### 6.6 `core/llm_client.py` —— **本期不改**

Phase 1 不在 LLM 请求/响应处接钩子。`llm_logger.py` / `log_sanitize.py` 继续以现有方式工作。Phase 2 加 `LLMRequest`/`LLMResponse` 事件后再迁。

## 7. 与现有机制的交互

| 现有机制 | 交互 | 备注 |
|---|---|---|
| `ToolResult` | PostToolUse 通过 `HOOK_OUTPUT_STATUS` 拿到 `[DONE/CHANGED/...]` 前缀 | 钩子可据此做"只在 CHANGED 时记录" |
| `MAX_TOOL_CALLS` / `MAX_TOOL_CALLS_PER_ROUND` | **钩子阻断仍计数** | 防止钩子被用来绕过 loop guard |
| `LoopDetector`（重复调用指纹） | 阻断的 `tool_input` **照常入指纹** | 模型重复戳同一被阻工具，指纹会命中触发 `_force_conclusion` |
| `ProgressTracker` | 阻断/注入后的 `tool_result` 文本进入相似度比较 | 期望：阻断消息差异化（带 reason），不会被识为"无进展" |
| `BudgetController`（wall-clock） | 钩子耗时**计入** wall-clock | 钩子慢 → 预算紧，符合直觉 |
| `microcompact` / `auto_compact` | 不受钩子影响 | Phase 2 再加 `CompactBefore/After` |
| `ToolDispatcher` | 不动 | 钩子在 dispatcher 调用**外面**包裹 |
| `safe_path` / `run_bash` 黑名单 | 仍是第一道防线 | 钩子是**额外**的策略层，不是替代 |

## 8. Windows / 编码

- 钩子 subprocess 走 `utils/encoding_utils.py::safe_subprocess_run`，避免 CP936 乱码
- `shell=True` 下，钩子作者写 `python hooks/foo.py` 比写复杂 inline shell 安全
- 环境变量值用 `str` 强转（Python subprocess on Windows 拒绝非 str），UTF-8 序列化 JSON 时 `ensure_ascii=False`

## 9. 失败/性能/安全

| 维度 | 处理 |
|---|---|
| 钩子崩溃 | except 兜底，记日志，按 exit 0 继续 |
| 钩子超时 | 30s 硬切，记日志，按 exit 0 继续 |
| 钩子 fork 开销 | 每个钩子约 30–100ms；无配置时跳过路径 < 1µs；建议在 README 提示"钩子越多越慢" |
| 钩子写穿仓库 | 信任门 + 用户自己写脚本时 `safe_path` 不强制 —— 钩子是**受信任代码** |
| 钩子读敏感数据 | `HOOK_TOOL_INPUT` 已截断；如需脱敏由钩子自己做（典型用法之一） |
| 并发 | 多个事件按注册顺序串行执行；同一事件多个钩子串行 |

## 10. 测试计划

新增 `tests/test_hook_manager.py`，覆盖：

- 配置缺失 → `is_active()=False`，`run_hooks` 返回空 result（不报错）
- 信任标记缺失 → 同上
- `matcher` 精确/`"*"`/缺省匹配

集成测试（轻量）：mock 一个钩子让 `bash` 工具在 `PreToolUse` 被阻 → 主循环收到合成 `tool_result`，loop guard 计数 +1。

## 11. 迁移路径

| 现有逻辑 | Phase 1 | Phase 2 |
|---|---|---|
| `utils/llm_logger.py` | 保持原状 | 迁成 `LLMRequest`/`LLMResponse` 钩子 |
