# 数据库连接支持方案

> 编写日期：2026/05/22
> 适用版本：当前 `develop` 分支（已包含 SSH 远程主机、SQLite 状态层、LLM 调用日志）
> 目标：让 Lead / Subagent / Teammate 都能在受控的关系型数据库上完成查询、写入、DDL、批量导入导出，凭据管理与防护体系对齐已有的 SSH 模式。

---

## 一、设计目标

把"模型只能在本机 / 远程 shell 里跑命令"扩展为"模型可以在一组**受控的数据库实例**(预登记 / 运行时注册皆可)上以同样的语义工作",要满足:

1. **统一连接形态**:用一组通用参数 `(username, password, hostname, port, service_name)` 描述任何被支持的 DB,LLM 不需要关心底层是 Oracle / MySQL / PostgreSQL / SQL Server;`service_name` 在不同 DB 上分别映射:
   - Oracle:`SERVICE_NAME`(也兼容 SID)
   - MySQL / PostgreSQL / SQL Server:`database`(库名)
2. **分层凭据策略**(对齐 `utils/ssh_client.py`):
   - **预登记**(`.team/db_hosts.json` + `password_env` 环境变量):密码不进 LLM history
   - **运行时注册**(`db_add_host(...)`):密码作为工具入参进 history,仅推荐一次性内网测试
   - 明文密码**禁止落盘**:`_load_host_configs` 强校验 `db_hosts.json` 中不得出现 `password_plain`
3. **完整数据操作**:`SELECT / INSERT / UPDATE / DELETE / DDL / 批量导入导出`,且事务边界显式可控
4. **复用现有防护层**:所有数据库工具返回 `ToolResult(content, changed, done, error)`,让 `ProgressTracker` 与 `LoopDetector` 照常生效
5. **连接复用**:同一 host 多次调用复用一个连接 + 游标,避免每次工具调用都付 TCP/握手与认证的开销
6. **行数与结果体积约束**:与 `run_bash` 的 `MAX_OUTPUT_BYTES=50_000` 一致;查询自动 `LIMIT` 兜底
7. **多层 Agent 同步纪律**:Lead 工具表(`tools/tool_dispatcher.py`)、Subagent 硬编码工具表(`agents/subagent.py`)、Teammate 硬编码工具表(`managers/teammate_manager.py`)按 `CLAUDE.md` 的同步约定统一加
8. **优雅退出**:`ShutdownManager` 钩子关闭所有连接,避免 DB 端僵尸会话占用许可证(Oracle 按会话计费的尤其关键)

## 二、技术选型

| 维度 | 选择 | 理由 |
|---|---|---|
| 抽象层 | **自研轻量抽象 `DBPool` + driver registry** | 仿照 `utils/ssh_client.py::SSHPool` 的形态,统一 `(host, query/exec/...)` 入口;不引入 SQLAlchemy 是因为本项目工具粒度本就细,ORM 反而要求 LLM 理解模型层 |
| Oracle 驱动 | **`oracledb>=2.0`** | 原生 Python 实现的 "thin mode" 不需要 Instant Client,Windows 友好;`cx_Oracle` 已被官方更名为 `oracledb` |
| MySQL 驱动 | **`PyMySQL>=1.1`** | 纯 Python,跨平台无 wheel 问题;`mysqlclient` 性能更高但要 C 编译器 |
| PostgreSQL 驱动 | **`psycopg[binary]>=3.1`** | psycopg3 自带 binary wheel,接口比 psycopg2 更现代 |
| SQL Server 驱动 | **`pymssql>=2.3`** | 纯 Python,无需 ODBC;若用户已装 ODBC Driver 可换 `pyodbc`(可选) |
| 否决:SQLAlchemy | / | LLM 不需要 ORM;原生游标更贴近"我把 SQL 发出去 → 我拿回行"的心智模型 |
| 否决:统一走 ODBC | / | Windows 上要装额外驱动;Linux/Mac 上 ODBC 链路尤其折腾 |
| 凭据存储 | `.env`(预登记密码) + `.team/db_hosts.json`(host 元数据) + 进程内存(运行时 host) | 与 SSH 模式完全一致,`.gitignore` 已覆盖 `.team/` |
| 行数 / 字节兜底 | `MAX_ROWS=1000`、`MAX_OUTPUT_BYTES=50_000` | LLM context 友好;超出时截断并提示 |
| 编码 | 全部按 UTF-8 处理,驱动级 client charset 强制设 utf8/utf8mb4 | 避免 Oracle `WE8ISO8859P1` 等老库的中文乱码 |

`requirements.txt` 增量(按需安装,不强制全装):
```
oracledb>=2.0          # Oracle
PyMySQL>=1.1           # MySQL / MariaDB
psycopg[binary]>=3.1   # PostgreSQL
pymssql>=2.3           # SQL Server
```

## 三、凭据模型(对齐 SSH 三档)

```jsonc
// .team/db_hosts.json
{
  "hosts": [
    {
      "name": "prod-oracle",         // LLM 引用用的别名
      "dialect": "oracle",            // oracle | mysql | postgres | mssql
      "hostname": "10.0.1.50",
      "port": 1521,
      "service_name": "ORCLPDB1",     // Oracle SERVICE_NAME / 其他 DB 的库名
      "username": "report_ro",
      "password_env": "PROD_ORACLE_PWD",   // 必须;明文 password_plain 禁止落盘
      "allowed_schemas": ["REPORT", "PUBLIC"],  // 白名单 schema/库;空数组 = 不限
      "default_max_rows": 1000,
      "read_only": true,              // 为 true 时 db_execute/db_ddl/db_import 直接拒
      "description": "生产 Oracle 只读"
    },
    {
      "name": "dev-mysql",
      "dialect": "mysql",
      "hostname": "127.0.0.1",
      "port": 3306,
      "service_name": "appdb",        // 这里是库名,不是 Oracle SERVICE_NAME
      "username": "dev",
      "password_env": "DEV_MYSQL_PWD",
      "allowed_schemas": [],
      "read_only": false,
      "description": "开发 MySQL,全权限"
    }
  ]
}
```

`HostConfig` dataclass 关键字段:
```python
@dataclass(frozen=True)
class DBHostConfig:
    name: str
    dialect: str                      # oracle | mysql | postgres | mssql
    hostname: str
    port: int
    service_name: str                 # Oracle = SERVICE_NAME;其他 DB = database
    username: str
    password_env: Optional[str]       # ② 预登记
    password_plain: Optional[str]     # ③ 运行时,仅内存
    allowed_schemas: Tuple[str, ...]
    default_max_rows: int
    read_only: bool
    description: str
    is_runtime: bool
```

**校验规则**(与 `_load_host_configs` 相同思路):
- `dialect` 必须在 `{oracle, mysql, postgres, mssql}` 内
- `password_env` 与 `password_plain` 严格互斥,前者只能从 JSON 加载,后者只能由 `db_add_host` 设置
- `read_only=true` 的 host 上,任何写操作工具直接返回 `ToolResult(error=True)`,**不下发 SQL**
- `allowed_schemas` 非空时,所有解析出的目标 schema 必须在白名单内(见 §五)

## 四、连接抽象 `utils/db_client.py`

集中放 driver registry、连接池、行级 / 批量执行。**绝不在 utils 之外直接 import 任何 DB 驱动**,保持依赖封闭。

```python
# utils/db_client.py 骨架(仅签名)

class _Driver(Protocol):
    """每个 dialect 一个 driver 实例。屏蔽各家 API 差异。"""
    def connect(self, host: DBHostConfig) -> Any: ...               # 返回原生 connection
    def cursor(self, conn: Any) -> Any: ...                         # 返回原生 cursor
    def quote_identifier(self, name: str) -> str: ...               # "FOO" / `foo` / [foo]
    def list_tables_sql(self, schema: Optional[str]) -> str: ...
    def describe_table_sql(self, table: str, schema: Optional[str]) -> str: ...
    def ping(self, conn: Any) -> bool: ...                          # 存活检查

_DRIVERS: Dict[str, _Driver] = {
    "oracle":   _OracleDriver(),
    "mysql":    _MySQLDriver(),
    "postgres": _PostgresDriver(),
    "mssql":    _MSSQLDriver(),
}


class DBPool:
    """进程级连接池,线程安全。"""

    def __init__(self) -> None:
        self._hosts = _load_host_configs()
        self._runtime_hosts: Dict[str, DBHostConfig] = {}
        self._conns: Dict[str, Tuple[Any, Any]] = {}   # name -> (conn, cursor)
        self._tx_state: Dict[str, bool] = {}           # name -> 是否在事务中
        self._lock = threading.Lock()

    # —— 业务 ——
    def query(self, name: str, sql: str, params: Optional[Sequence] = None,
              max_rows: Optional[int] = None) -> Tuple[bool, str]: ...
    def execute(self, name: str, sql: str, params: Optional[Sequence] = None) -> Tuple[bool, str]: ...
    def execute_many(self, name: str, sql: str, rows: Sequence[Sequence]) -> Tuple[bool, str]: ...
    def commit(self, name: str) -> Tuple[bool, str]: ...
    def rollback(self, name: str) -> Tuple[bool, str]: ...
    def list_tables(self, name: str, schema: Optional[str] = None) -> Tuple[bool, str]: ...
    def describe(self, name: str, table: str, schema: Optional[str] = None) -> Tuple[bool, str]: ...
    def ddl(self, name: str, sql: str) -> Tuple[bool, str]: ...
    def import_csv(self, name: str, table: str, local_csv: str, *,
                   has_header: bool = True, batch_size: int = 1000) -> Tuple[bool, str]: ...
    def export_csv(self, name: str, sql: str, local_csv: str,
                   params: Optional[Sequence] = None) -> Tuple[bool, str]: ...
```

**事务策略**:
- 连接默认 `autocommit=False`
- `db_execute / db_execute_many / db_ddl / db_import` 后**不自动 commit**,必须显式调 `db_commit`(或 `db_rollback`)
- LLM 一旦执行第一条写操作,`_tx_state[name]=True`,所有 `read_inbox` 预处理消息里会插一条 `<pending-transaction>` 提醒,促使模型在结束前显式处置事务
- `auto_compact` 触发时如果有 `pending-transaction`,强制注入提示,但不替模型决定提交还是回滚

**结果格式化**(给 LLM 看的 `content`):
- 查询结果用紧凑表格(列头 + 截断行):
  ```
  COLS: id | name | created_at
  001 | 张三 | 2026-05-22
  002 | 李四 | 2026-05-22
  ... (12 行,显示前 2 行)
  ```
- 写操作返回 `affected_rows=N`(以及 `[CHANGED]` 状态前缀)
- 截断按行数 + 字节双兜底,与 SSH 一致

## 五、安全防护

| 风险 | 防护 |
|---|---|
| 跨 schema 写越权 | `allowed_schemas` 白名单。SQL 通过 `sqlparse` 解析提取目标 schema,不在白名单则**拒发**。无法解析的 SQL 视为可疑,拒发并要求 LLM 显式拼 schema |
| 任意 DROP / TRUNCATE | `db_ddl` 工具独立、需要 `read_only=False` 且 host 显式声明 `allow_ddl=true`(`db_hosts.json` 新增字段);否则不挂载该工具 |
| 长查询拖垮 DB | 每次 query 设 `statement_timeout`(PG 原生支持;Oracle 走 `OCI_ATTR_CALL_TIMEOUT`;MySQL 走 `MAX_EXECUTION_TIME` hint);默认 30s,可入参覆盖 |
| 巨大结果集 | `MAX_ROWS=1000` 默认;`fetchmany` 而非 `fetchall`;超出时截断并提示 |
| SQL 注入 | LLM 自己拼 SQL 时强制建议用占位符(query/execute 都接受 `params`)。但**不强制**——LLM 是 trusted caller,占位符更多是为防止它误把表名当数据 |
| 凭据泄露 | `password_env` 路径同 SSH;`db_list_hosts` 不回显 password;`db_add_host` 返回中也不回显;LLM 日志(`.logs/`)记的是 payload,DB 驱动的 password 不进 LLM payload |
| 误删表 | `db_ddl` 检测 `DROP TABLE` / `TRUNCATE` 时要求 SQL 里带显式的二次确认令牌(如 `-- CONFIRM: <表名>` 注释行),否则拒发——同 `tools/base_tools.py::run_bash` 黑名单思路 |
| 远端审计 | 连接时 DB 端 `MODULE='gena-agent'` / `application_name='gena-agent'`,方便 DBA 在 v$session / pg_stat_activity 里识别 agent 流量 |

## 九、与现有体系的衔接

1. **`utils/loop_control.py::ToolResult`**:每个工具返回的 `changed` 必须如实反映"DB 状态有没有变":`db_query / db_describe / db_list_*` 永远 `changed=False`(让 `ProgressTracker` 知道纯查询不算"进展");`db_execute / db_commit / db_ddl / db_import` 成功时 `changed=True`,失败时 `changed=False`(参考 `tools/ssh_tools.py::_wrap`)
2. **`auto_compact`**:摘要模板里要提示模型"如果存在 pending DB 事务,在摘要后第一步必须 commit 或 rollback"
3. **`LLM 调用日志`**(刚加的 `.logs/`):SQL 已经在 `messages` 里,默认就被记录。**不需要**额外把执行结果再 dump 一份——`tool_result` 段已经在 messages 中
4. **`background_manager`**:导入 / 导出大文件耗时长的场景,后续可以加 `background_db_import`,把工具结果走通知队列,与 `background_ssh_exec` 同一形态
5. **`encoding_utils`**:不参与——DB 驱动各自做编码协商,这一层不再叠

## 十、开放问题(实施时再决)

1. **连接保活策略**:Oracle / PG 都有 server-side timeout,空闲连接会被 RST。当前打算和 `SSHPool._get_conn` 一样在取连接前 `ping`;但 Oracle `ping` 成本不低(一次 round-trip),要不要按"上次使用 < N 秒就跳过 ping"做缓存?
2. **`fetchmany` 分页对 LLM 的暴露面**:目前只截断不分页;如果用户经常需要查超过 1000 行,要不要加 `db_query_page(host, sql, page, page_size)`?倾向**不加**——LLM 该改 SQL 加 `WHERE / LIMIT`,而不是翻页
3. **`db_explain`**:Oracle / PG / MySQL 的 `EXPLAIN` 输出差异大,要不要做一个统一抽象?暂不做,LLM 可以 `db_query("EXPLAIN ...")` 自己看
4. **`SQLite` 与 `.gena.db`**:本项目内置 SQLite 状态库,要不要把 SQLite 也作为一个 dialect 暴露?**不**——会让 LLM 有权写状态库,污染 TaskManager / MessageBus,风险大于收益
5. **审计日志**:是否额外在 `.logs/db_<ts>_<pid>.jsonl` 里再单独写一份"SQL + 影响行数 + 调用方 agent"?DBA 友好但与 LLM 日志重复;先**不做**,等真有需求再补
